# 本地会话、上下文与 token 保护

## 完整历史与会话承接

从本版起，生活馆聊天和桌面工作台聊天均写入 `%APPDATA%/NiangaoPhotoPet/chat.sqlite3`，并在 `chat_sessions/<会话ID>.json` 保留逐会话快照。原始消息不因摘要、换模型、关闭程序或新建一轮而自动删除；请求未完成的用户消息及错误也会保留。旧版只在内存里的、升级前未落盘聊天无法自动恢复。

每次发送给 API 的上下文独立于本地历史。程序不再暗中只截取最近八条，而是读取当前会话的承接摘要、最近消息和本轮消息，并附加最新年糕档案。API 的上下文窗口仍有上限，本地历史没有程序设置的条数或 token 清理上限，但受可用磁盘空间约束。

达到所选模型的摘要阈值时：先用同一接口生成简短事实摘要，再创建新的会话ID、JSON文件和会话选择项；新一轮携带摘要及最近最多六条消息，原会话保留。若最近消息本身过大，会减少携带数量或再次摘要，防止超窗。若单条输入连同档案仍无法放入窗口，会在联网前拒绝，并保留原文。摘要失败停止本轮，不清除历史、不伪造承接回复。

摘要是有损的承接资料，不等于永久完整记忆；原文可在“聊天历史”按中国日期分页回看，选中查看完整正文，也可导出全部 JSON。实时对话区显示当前会话最近150条，日期浏览每页100条，翻页和导出不受该显示页数限制。新建一轮不再意味着删除历史。

## 模型阈值与实时 token

地址、协议和模型组合分别保存上下文窗口、摘要阈值及最近消息数量。DeepSeek 官方预设采用可编辑示例：窗口128,000、阈值110,000；其他未配置模型采用保守示例：窗口32,768、阈值28,000。这些不是自动获取的服务商规格，请按实际账户与型号核对并在设置中修改。

发送前没有各厂商的官方 tokenizer，本版明确显示离线估算与 UTF-8 保守预算，包含系统提示、最新年糕档案、摘要、历史和正在输入的消息。不是官方精确计数，保守预算可能提前触发摘要。收到 API `usage` 后，实际用量按服务商返回值记账；不得把估算或本地余量说成真实账户余额。

## 每日额度

默认本程序每日上限500,000 token，已用80%时提示，可在设置调整上限与提醒百分比。生活馆、工作台、自动摘要、连接测试和 AI 日记共享账本。按中国标准时间日期统计；启用服务端校时后使用已校准时钟。跨午夜请求归发起日。

联网前用输入保守预算加输出上限做事务性预留，两个窗口同时发送也不能分别把同一份余量放行。余量不足则不发送。返回真实用量后按实际核销；未返回 usage、超时或计费不明的失败保守计入“估算/预留”，重启不会清零。明确拒绝请求的常见4xx按未生成记0。不同服务商对缓存、推理及计费的定义不同，账本不是人民币/美元费用上限，不能统计其他程序或网页的用量。

输入、输出及服务商报告的思考token计入总数；OpenAI输出中已包含的reasoning细项不再重复相加，Anthropic缓存字段和Gemini思考字段按其协议计入。摘要本身也消耗额度。没有自动重试付费请求，也不会自动增大额度。

## 轻量思考

本版只允许轻量策略，每次输出上限最多2,048 token，不再自动提高到8,192。DeepSeek普通聊天显式禁用thinking；OpenAI支持的模型使用low effort；Gemini按型号使用关闭/最低思考预算或low级别；支持的Qwen3服务关闭thinking。DeepSeek reasoner、R1、thinking专用等不可可靠限制的深思模型在请求前拦截，建议使用deepseek-chat。

第三方服务的内部实现无法由客户端绝对证明；客户端只发送明确的轻量参数、限制输出并按返回usage记账，不宣称所有服务内部都没有额外思考。

## 本地数据与备份

聊天文件是本机可读数据；API Key仍只在单独的Windows DPAPI文件内，不作为会话元数据保存。不要把密钥粘贴到普通聊天正文中。SQLite使用事务和WAL，逐会话JSON采用替换写入。程序不自动清理聊天，但“长期保留”不等于能抵抗用户删除、磁盘故障或空间耗尽。可通过历史页“导出全部历史 JSON”备份，或退出程序后备份整个用户数据目录。
